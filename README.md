# OmniDesk

An intelligent IT & HR support agent for internal employees. OmniDesk answers
policy and troubleshooting questions from a knowledge base, checks the status
of support tickets an employee already raised, and — when it can't answer
from the knowledge base — walks the employee through filing a Jira ticket,
with an explicit human confirmation step before anything is actually created.

## How it works

OmniDesk is a [LangGraph](https://langchain-ai.github.io/langgraph/) pipeline
fronted by a [Streamlit](https://streamlit.io/) UI:

```
query -> router --hr-----> hr_retrieve   -> hr_answer   -> (escalate if unanswered)
                --it-----> it_retrieve   -> it_answer   -> (escalate if unanswered)
                --both---> both_retrieve -> both_answer -> (escalate if unanswered)
                --status-> status_check
```

- **Router** — an LLM node classifies each query as `hr`, `it`, `both`, or
  `status` ([src/graph.py](src/graph.py)).
- **Retrieval** — hybrid (dense + sparse, fused with RRF) search over two
  [Qdrant](https://qdrant.tech/) collections: HR policy Q/A pairs and IT
  incident tickets ([src/retrieval.py](src/retrieval.py)). IT retrieval
  dedupes by issue "family" so near-duplicate tickets don't crowd out
  distinct root causes.
- **Answer** — the LLM answers strictly from retrieved context, or emits a
  fixed "I don't have enough information" phrase if the context doesn't
  cover the question.
- **Escalation** — an unanswered question routes to a two-step
  human-in-the-loop flow (`collect_ticket_info` -> `confirm_ticket`) before a
  real Jira ticket is created via `jira_utils.create_ticket`
  ([src/jira_utils.py](src/jira_utils.py)).
- **Status check** — for `status` queries, looks up the employee's existing
  Jira tickets by email and returns status + comments, read-only, no
  confirmation needed.

## Project layout

```
app.py                   Streamlit UI
src/
  graph.py                LangGraph pipeline (router, retrieval, answer, escalation)
  config.py                Shared config: Qdrant, embeddings, LLM, Jira settings
  retrieval.py              Hybrid search over Qdrant collections
  qdrant_utils.py            Collection creation + embedding/upsert helpers
  jira_utils.py               Jira REST API client (create ticket, look up status)
  ingest_hr.py                Loads the HR policy Q/A dataset into Qdrant
  ingest_it.py                 Loads the IT ticket dataset into Qdrant, clusters into issue families
  evaluate.py                   Retrieval-only eval (recall@k, MRR) across dense/sparse/hybrid
  evaluate_agent.py              Full-pipeline eval (router accuracy, faithfulness, abstention, ticket quality) via LangSmith
  eval_*.json                     Eval fixtures (some generated by ingestion, some hand-authored)
```

## Setup

Requires Python >=3.12 and [uv](https://docs.astral.sh/uv/).

```bash
uv sync
```

You'll also need a running Qdrant instance. The quickest way is Docker:

```bash
docker run -p 6333:6333 qdrant/qdrant
```

### Environment variables

Copy `.env` (or create one) in the project root with:

| Variable | Required | Purpose |
|---|---|---|
| `OPENAI_API_KEY` | recommended | Enables OpenAI for chat + embeddings. Without it, the LLM falls back to a local [Ollama](https://ollama.com/) model (`llama3.1:8b` by default). |
| `OPENAI_CHAT_MODEL` | optional | Defaults to `gpt-4o-mini`. |
| `OPENAI_EMBEDDING_MODEL` | optional | Only used if `EMBEDDING_PROVIDER=openai`; defaults to `text-embedding-3-small`. Otherwise embeddings run locally via `fastembed`. |
| `QDRANT_URL` | optional | Defaults to `http://localhost:6333`. |
| `HF_TOKEN` | optional | Needed to download the HuggingFace datasets used for ingestion. |
| `JIRA_API_TOKEN` | for escalation/status features | Jira Cloud API token. Auth email and project are set in [src/config.py](src/config.py). |
| `LANGSMITH_API_KEY`, `LANGSMITH_TRACING`, `LANGSMITH_PROJECT` | optional | Enables LangSmith tracing and is required to run `evaluate_agent.py`. |

## Running it

### 1. Ingest the knowledge base

Populates the two Qdrant collections and writes eval fixtures. Run once
before first use, and again whenever you want to rebuild from scratch (both
scripts drop and recreate their collection):

```bash
cd src
uv run python ingest_hr.py
uv run python ingest_it.py
```

### 2. Launch the app

```bash
uv run streamlit run app.py
```

Ask an HR or IT question, or ask about the status of a ticket you've already
raised.

### 3. Run evals

Retrieval-only eval (recall@k / MRR across dense/sparse/hybrid):

```bash
cd src
uv run python evaluate.py
```

Full-pipeline eval (router accuracy, answer faithfulness, abstention/escalation
correctness, ticket quality) — uploads results to LangSmith:

```bash
cd src
uv run python evaluate_agent.py                # runs all four
uv run python evaluate_agent.py router          # or just one
```
